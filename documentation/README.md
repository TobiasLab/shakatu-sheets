# Documentation

Project documentation is grouped by concern:

- [`architecture`](architecture/): system boundaries and architectural decisions.
- [`database`](database/): schema, migrations, persistence, and data lifecycle.
- [`dependency_management`](dependency_management/): dependency policy and upgrade notes.
- [`design`](design/): product behavior and recognition UX; the [design language](design/design-language.md) defines shared
  visual and interaction conventions.
- [`development`](development/): local setup, testing, packaging, and release workflows.
- [`misc`](misc/): research and notes that do not belong in the other sections.

Prefer short documents with one clear purpose. Update existing documentation instead of creating overlapping sources of
truth.
